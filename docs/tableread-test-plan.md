# Table Read Test & Eval Plan (MVP)

Three layers: conventional tests (deterministic, mock LLM), contract checks, and LLM evals (real API, gated). All fixture references are to `tableread-fixture.json` ("The Long Pour").

## 1. Conventional tests (run on every PR, mock LLM only)

**Backend unit (pytest):**

- Snapshot semantics: every mutating endpoint creates exactly one snapshot (with full materialized `doc` + `ledger` + `flags`); undo restores `projects.doc`, `ledger_facts`, and `consistency_flags` byte-identical to the parent snapshot in one transaction — **the undo-orphan case**: accept a beat that creates facts + flags, undo, assert those facts and flags are gone and prompt context bundles no longer include them; undo at root → 409; snapshot tree parentage correct after undo-then-edit (fork); post-undo, a stale draft Change Set applies → `PREVIEW_STALE`.
- Restore to ancestor (adoption A5): `POST /projects/{pid}/restore` with a proper ancestor restores doc+ledger+flags byte-identical; non-ancestor / current head → 409 `VALIDATION`; `GET /projects/{pid}/snapshots` returns nearest-parent-first ancestors (≤20); empty snapshot instruction rejected (`EmptyInstruction`).
- Suggestion carousels (adoption A4): `POST /suggest` returns 3 strings; chips insert-only (no auto-generate); context includes latest accepted beat script / optional draftScript.
- Write keyboard (adoption A8): Q/W/Tab/Enter/Esc/1–3 work when canvas unfocused; keypresses inside script textarea never fire shortcuts.
- Import transaction: import returns `{project, newFacts, consistencyFlags}`; all import-derived facts `pending_review` even at confidence 0.95; import-time scan flags persisted `open`; parse failure or mid-transaction fault → zero rows changed.
- Parallel import progress (T7.12): scene-level segmentation/fact extraction/consistency work uses no more than `IMPORT_LLM_CONCURRENCY` workers (default 8 since 2026-10-13; was four); collected project output is applied in source scene order regardless of worker completion order; each stage's progress SSE frames are monotonic (`done` never decreases, never exceeds `total`, and eventually reaches `total` on success); `Done` is not emitted/rendered for a stage until all assigned scenes complete and the next stage begins; any worker exception or downstream stage failure emits one terminal `failed` event and leaves zero project-scoped rows.
- Import act inference (T7.13): compact post-segmentation summaries produce ordered `InferredActBreaks.starts`; the server expands them into a total partition with exactly one act per scene. Cover multi-act assignment, first start at act 1 (empty Cold Open), skipped middle/trailing acts, no-cold-open formats, and unchanged source scene order/ids/beats/text. Missing scene-zero, duplicate/non-increasing/out-of-range act or scene starts trigger exactly one semantic retry; a valid repair succeeds, while a second invalid result surfaces `SCHEMA_INVALID_LLM` and leaves zero projects, snapshots, facts, flags, Change Sets, or idempotency rows.
- Import progress/cost (T7.13, T7.32): SSE stage order is `parsing_scenes` → `segmenting_beats` → `inferring_acts` → `inferring_entities` → `inferring_promises` → `inferring_overview` → `extracting_facts` → `checking_consistency` → `saving`; singleton analysis stages emit no scene progress. Preflight estimates use nominal `2N+5` calls (Opus story breakdown + Haiku facts/scan), with repair/chunking calls explicitly caveated. Narrative Map is a separate, user-triggered durable run: one source-backed `import_analyst` call per scene, `import_analyst` macro synthesis, and independent `writer`-role verification. It checkpoints each accepted scene, retries one rejected scene once with deterministic evidence diagnostics, rejects unsupported maps, and cannot discard the import. T9.12: every persisted map quote (theme, act turn, escalation, arc turn, scene turn, Hero's Journey stage, thread movement, synthesized thread setup/payoff) prefers the cited beat's substantive dialogue over a leading parenthetical, and a beat whose only line is too short for `quote_for_beat` still gets a non-empty quote.
- Import `found` frames (import board, 2026-10-12; data contract §9.3): one import through `MockLlmClient` streams exactly one `scenes` frame (N cards, `intExt` and line counts from the split), one `scene` frame per scene index with `beatCount` matching the result, one `acts` frame with N `sceneActs`, one `castRead` per entity chunk, one post-merge `cast` frame (top 12 by speaking-scene count, cue lines resolved with the whole-script shooting-script decision), one `threads` frame whose setup/payoff indexes match the episode threads, one `overview` frame, one `facts` frame per scene, and one `flags` frame with severity counts. A segment that fails twice emits `{kind: 'scene', failed: true, beatCount: 1}`, never an empty success. Cached replay: a resume with the same Idempotency-Key after a mid-facts failure re-emits saved `scene`/`facts` units and checkpointed singleton results with `cached: true`, identical to the first run's data, while freshly computed units stay `cached: false`. No `found` frame contains any beat's `scriptText`. Log privacy (rule 5): `import_found` log lines carry the run id, stage, kind, cached and a count only, never a slugline, reading, thread label or logline. `intExt` unit tests cover scene numbers, `INT./EXT` and `EXT/INT` (other) and an empty slugline. Existing `stage`/`progress` frames are unchanged. Contract: `ProjectImportProgressEvent` accepts every `found` kind, defaults `cached` to `false`, and rejects a negative index or an unknown kind.
- Beat reading on the import board (T9.17, 2026-10-13; `test_import_found.py`): each `scene` frame's `beats` are the saved scene's beats' `whatHappens`, `audienceLearns` and `audienceFeels`, in order, and nothing else; **no `found` frame contains a `scriptText` key or any line of the script body** (sluglines excepted); a failed unit sends `beats: []`; a resume's cached `scene` re-emits carry the same beats; `import_found` log lines hold no beat text. Contract: a `scene` frame without `beats` parses with `beats: []`.
- Faster import (2026-10-13, Phase 1 speed-ups): **AI client** (`test_llm_timeout.py`, `test_llm_anthropic_client.py`, `test_llm_mock.py`) — an overload (429, 529, 5xx other than 504) retries up to four attempts with 2/4/8 s backoff, honors `retry-after`, never waits more than 60 s in total, logs each wait with numbers only, and never retries a 400, a 504 or a timeout; the `llm_call` line carries numeric `elapsed_ms` and `ttft_ms` (`-` for a plain call); `prewarm_cache` sends the real op's request (tools, system, `tool_choice`, thinking/effort, cache breakpoints) with `max_tokens=0`, falls back to 1 after a 400 about it and remembers that, swallows and logs every error, never validates the reply, and the mock records it. **Pipeline** (`test_import.py`, `test_import_overlap.py`) — `TABLEREAD_IMPORT_CONCURRENCY` defaults to 8 and clamps to 1–16; each fan-out stage prewarms once and then runs every scene together (no scene runs alone first); overlap mode (threads, overview and facts→continuity side by side after the cast merge) saves a project doc, ledger facts and flags byte-identical to the serial path (`TABLEREAD_IMPORT_OVERLAP=0`, concurrency 1), with identical prompts and the same event sequence (types, stages and counters in order; `found` payloads compared as a set, since facts land in completion order); with a slow fake client the late stages run side by side (wall time well under serial); a resume after a facts failure re-calls neither threads nor overview; a failed branch checkpoints its finished siblings and surfaces its own error code; in both modes a failure (a facts outage, an overview schema failure) stops the run at the stage that failed (last `stage` frame and `ImportRunRow.phase`), after every earlier stage has merged and shown its `found` frame; the first failed scene cancels the scenes not yet started and no consistency scan starts.
- Import entity inference (T7.15): `merge_inferred_entities` mints a new character with the model's `aliases` when a name doesn't resolve, extends an existing (unlocked) row's `aliases` on a name/alias/prefix match, and never modifies a `locked: true` row's own fields — only its id is used to resolve relationships; a relationship whose either `betweenNames` fails to resolve is dropped and counted, never persisted; world elements land as `worldQA` entries (`Where`/`What is <name>?`); `normalize_known_by`/`_alias_match` resolve a `knownBy` name against a character's `aliases`, not just its display name; T9.8: an inferred character attaches only when its name and aliases together hit exactly one row ("Joshua Lyman" with alias "Josh" attaches to Josh), hitting several rows mints nothing and files one `[merge_proposal]` scene flag ("Mallory O'Brien" vs "Mallory" + "O'Brien"); `normalize_known_by` mints no role phrase, filler ("<unknown>"), name absent from the script, or name matching several rows (a full-name knower cannot bring back the row the proposal withheld); a cue counts only with dialogue under it once most of the script's cues have it; schema-invalid `infer_story_entities` output after the client's one retry fails the import atomically (`SCHEMA_INVALID_LLM`, zero rows) — same contract as segmentation/act inference. `inferring_entities` SSE stage runs between `inferring_acts` and `extracting_facts`.
- Cast management (T7.16): rename PATCH updates `name` and snapshots once; PATCH editing only `aliases` leaves `name` untouched; empty body → 400 `VALIDATION`; missing character → 404; a `locked: true` character → 409, zero mutations. Merge absorbs the source's `aliases` and former name, rewrites every ledger fact's `knownBy` and every relationship pair atomically (one snapshot; undo restores the source character), drops a relationship that would self-pair after merge, and removes the source character; merge into self, or with a missing/locked source or target, or into a character referenced by a locked scene's motivation, is rejected (400/404/409) with zero mutations. Delete of a referenced character → 409 with reference counts; delete of an unreferenced or already-nonexistent character succeeds or 404s; delete of a `locked: true` character → 409 `LOCKED_OBJECT`.
- PDF extract: `extract_pdf` uses text-layer output when usable, falls back to injected OCR for scanned/image PDFs, rejects oversize/page-capped/empty inputs, maps missing Tesseract to `UNAVAILABLE`, and never calls the LLM. PR-path tests inject text/OCR engines so CI does not require system Tesseract.
- PDF extract route: multipart `POST /projects/import/extract-pdf` returns `PdfExtractResult`, rejects non-PDF uploads with the canonical error envelope, logs only byte/page/method/duration/warning metadata, and creates no project, snapshot, Ledger row, or Change Set.
- Change Set preview integrity: apply writes exactly the stored `preview` payload (assert no LLM client calls during apply — mock records zero invocations); apply with `preview: null` → 409; mutating the project between preview and apply → 409 `PREVIEW_STALE`; `after` display snippets derived from, never parsed back into, the typed payload.
- Supersede atomicity: confirming a supersede proposal flips proposal→`active` and target→`superseded`/`supersededBy` in one transaction (crash-injection test: no state where one is updated without the other); reject leaves target `active`; confirm on non-pending fact → 409; confirm when target already superseded → 409 `CONFLICT_STALE_PROPOSAL`.
- Lock enforcement (the non-negotiables):
  - `apply` with any locked objectId → 409, zero mutations (verify full doc equality).
  - `regenerate_elements` mock response containing an unrequested/locked id → rejected, logged, 502 `SCHEMA_INVALID_LLM`.
  - Scene `locked: true` → all child beats treated as locked (fixture: lock scene-1, attempt beat-1-1 regen → 409).
- Ledger policy: confidence < 0.8 → `pending_review`, excluded from context bundles; contradiction → supersede proposal, original untouched; reject → status `rejected` + excluded; edit → `writer_authored` (+ `pending_review` → `active`); source-beat regenerated → dependent facts flagged `stale`; null `proposedReplacement` mints empty `fact` (stored-null); confirm of retirement proposal supersedes target and rejects proposal (`writer_confirmed`); proposals against non-active targets dropped at mint.
- Ledger mutations are snapshotted: confirm/reject/edit each create one snapshot; batch confirm/reject creates exactly one snapshot for the batch and fails atomically on any invalid id (incl. mid-batch stale supersede target → 409 `CONFLICT_STALE_PROPOSAL`); undo after batch-accept restores all facts to `pending_review`.
- Save-field-only path: structural PATCH triggers `scan_consistency` and returns flags; non-structural PATCH (location, time) does not; PATCH into a locked range → 409 `LOCKED_OBJECT`; direct typing into a `scriptLocked` beat is rejected server-side, insertion before/after succeeds; reordering beats inside a locked scene → 409 `LOCKED_OBJECT` (sibling reindex in unlocked scenes still allowed).
- Scene act correction (T7.13): direct act PATCH moves the scene into any format-valid act, including an empty section; creates exactly one snapshot; makes zero LLM/extraction/consistency calls; and is rejected with `LOCKED_OBJECT` and no snapshot for an effectively locked scene/episode.
